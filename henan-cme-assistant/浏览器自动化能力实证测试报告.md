### 测试 A：bu 平面（页面级自动化，可读 DOM）

| 读取 DOM（元素位置/事件日志/视口） | ✅ `bu.js`/`bu.snapshot` 直接返回结构数据 |
| `bu.drag` 拖动（按下→移动→松开） | ✅ 方块 client (311,238) → (610,276)，水平移动 299px |

| 位置观察 | ✅ DOM 前后回读（getBoundingClientRect + style）与截图一致 |

### 测试 B：cu 平面（真实 OS 鼠标，控制本机 Edge/桌面）

| 项目 | 结果 |
|---|---|
| 初始化 | ⚠️ 首次被 Windows 空密码策略拦截（PiP 虚拟桌面不可用），重试后切主桌面成功 |

| 坐标校准 | ✅ 页面自报 client ↔ 屏幕映射确认（client(375,251) ↔ screen(667,308)，x≈0.472、y≈0.79 单位/px） |
| `cu.drag` 拖动（按下→移动→松开） | ✅ `cu.drag(665,329,785,329)`：DOM 日志确认 `pointerdown/mousedown client=(371,278)` 落在方块上 → 一串 mousemove → `mouseup`；方块 `style.left` 300px→559.6px（水平移动 259px），垂直方向 style.top 未变；页面自报鼠标终点 client(620,278) |
| 拖动轨迹粒度 | ⚠️【已验证】事件日志显示按下点附近有约 45 次同坐标抖动后**一次大跳**到终点再松开——cu.drag 是「按下+抖动+单次大跳+松开」的**粗粒度路径**，不是平滑多步路径 |
| 普通点击 | ✅ 有间接实证：`cu.click` 成功切换了浏览器标签页（点到课程页标签）；cu.drag 中的 mousedown+mouseup 也证明按键输入可达页面 |
| 读取页面 DOM | ❌ cu 只能看屏幕截图，**不能读取页面 DOM** |

### 关键限制（【已验证】或标注推测）

1. **cu 全屏坐标对窗口布局变化脆弱**：截图与动作之间若窗口切换/移动，点击会落到别的窗口——测试中实测发生过一次（点击落到了用户的好医生 CME 窗口，无破坏）。【已验证】
2. **cu 不能读 DOM**：真实 Edge 页面内的元素位置只能靠截图目测，无法拿到 getBoundingClientRect 等精确值。【已验证】
3. **bu 是独立产品浏览器**：bu 的标签列表里只有它自己的页面；用户本机的 Edge 会话（课程页、登录态、油猴、扩展）bu **不可见**。【已验证】
4. **cu.drag 轨迹粗糙**：单次大跳路径，中间坐标不连续；对「要求拖动轨迹平滑/有 Y 波动」的组件会被一眼识破。【已验证】
5. cu 平面可用性依赖 Windows 账户策略（空密码会拦 PiP，需主桌面回退）。【已验证】
6. 插件扩展的 content script 是**读真实 Edge 页面 DOM 的唯一可靠通道**：用户现场日志已证明（DOM 快照、播放器绑定、验证码诊断均来自 content script）。【已验证】

## 三、分开分析：普通网页拖动 vs 本站验证码

### 普通网页上的鼠标拖动能力（通用能力）

- **可以做到**：bu 平面 `bu.drag` 平滑多步拖动 + DOM 前后回读（端到端验证通过）；cu 平面真实 OS 鼠标 `cu.drag` 能完成按下→移动→松开并移动元素（验证通过），但轨迹粗。
- 结论：对普通 UI 拖拽（拖条、排序、滑杆），两个平面都具备可行能力；cu 需先校准坐标、动作前必须截图确认窗口布局。

### 本站滑动拼图打卡验证码（不得自动化）

- **不实现、不提供**：验证码是平台人机校验/反作弊（打卡 = 确认真人观看；源码注释「简单验证拖动轨迹，为零时表示Y轴上下没有波动，可能非人为操作」即反程序拖动），自动滑动属于绕过人机校验，本项目明确拒绝。
- 即使不考虑合规，技术上也**不可能干净地前端模拟通过**（【已验证】源码事实 + 本次实测推论）：
  1. 目标缺口位置 `destX` 每次随机（73~247 范围），前端不暴露，需读组件内部状态才算作弊；
  2. 轨迹检查要求 Y 轴波动，而 cu.drag 实测是「单次大跳」粗路径，bu.drag 虽是平滑路径但属纯水平无波动——两者都会命中「请再试一次」；
  3. 即便前端表现出「滑动成功」，打卡结果仍需平台服务端校验，前端无法伪造服务端验证结果。
- **必须人工完成**：弹窗出现时暂停自动流程、提示人工、人工完成后自动恢复——这正是当前插件已实现的行为，与本次重新确认的目标一致。

3. 无需引入鼠标自动化：切课是 DOM 点击（content script 已实现），验证码保持人工；cu/bu 能力测试结论不影响插件架构。
