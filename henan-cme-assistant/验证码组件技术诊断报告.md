# 滑动拼图打卡验证码组件 · 技术诊断报告

**目标站点**：https://yuancheng.henanyixue.com/（河南省继续医学教育学习平台，Vue 3 SPA，Vite 构建，静态资源位于 `/static/1.1.21/js/`）
**分析对象**：课程学习页验证码弹窗组件（`.vertifyWrap`）
**分析方式**：① 静态包源码逆向（主包 `index-aQ3C2asO.js`、播放器 `playVideo-ozoAdxN2.js`、学习页 `detail-C78Rx8MT.js`、接口转发 `remoteProject-Qczgthpf.js`）；② 插件诊断模块的被动 DOM/事件/Canvas 观察框架（见 `content.js` 诊断模块与《测试清单.md》）
**证据目录**：`_analysis/`（已下载的原始 JS/CSS 文件，文中标注的偏移量以 `index-aQ3C2asO.js` 字符偏移计）
**结论前置**：本报告只做技术诊断与可行性评估，**不提供任何自动通过验证码的实现**，插件在弹窗出现时暂停自动化、等待人工完成。

## 2. DOM 结构与关键属性【已验证事实】

### 2.1 弹窗外层与内部节点（与用户提供特征一致）

```

├── div.canvasArea                   ← 画布区，height:160px（CSS 固定）
│   ├── canvas[canvasRef]            ← 背景大图 canvas，宽=canvasWidth(默认320/页面262)，高160
│   └── canvas.block[blockRef]       ← 拼图块 canvas，宽=l+2r+3=63px，高160；position:absolute;left:0;top:0;cursor:grab
├── div.sliderContainer              ← 滑块容器，CSS 固定 width:310px;height:40px;line-height:40px;background:#f7f9fa;border:1px solid #e4e7eb
│   ├── div.sliderMask               ← 已滑过遮罩，position:absolute;left:0;top:0;height:40px;background:#d1e9fe;border:0 solid #486cd6；宽度随拖动增长
│   │   └── div.slider               ← 滑块，position:absolute;top:0;left:0;width:40px;height:40px；内含
│   │       └── div.sliderIcon       ← “→”箭头
│   ├── div.sliderText               ← 提示文字，默认「向右滑动填充拼图」；active/success/fail 时 display:none
├── div.refreshIcon                  ← 刷新按钮，position:absolute;right:5px;top:5px;width:30px;height:30px（点击=重置并换图）
└── div.loadingContainer             ← 加载遮罩，position:absolute;left:0;top:0;width:310px;height:155px;z-index:2;background:#edf0f2
    ├── div.loadingIcon              ← 旋转加载图标（animation .8s linear infinite）
    └── span「加载中...」
```

- 关键尺寸常量（组件源码）：
  - `l`（拼图边长）默认 **42**，`r`（圆角半径）默认 **9**；
  - 小块 canvas 宽度 `T = l + 2r + 3 = 42+18+3 = 63`（✅ 与现场观察 63×160 一致）；
  - `sliderContainer` 宽度 CSS 固定 **310px**（✅ 现场观察 ~320px 为含边框/近似）；滑块宽 **40px**；拖动范围受 `o<0 || o+38>=l` 限制（约 0–282px 可视行程）。

### 2.2 关键 CSS 状态类【已验证事实】

`sliderContainer` 类名随阶段切换（源码 `g` 变量 + CSS 规则）：

| 类名 | 触发阶段 | 视觉特征（CSS 已验证） |
|---|---|---|
| `sliderContainer` | 初始/静止 | 灰底、1px 边框 |
| `sliderContainer sliderContainer_active` | 拖动中 | 滑块/遮罩变蓝（`border:1px solid #486cd6`） |

## 3. Canvas 绘制分析【已验证事实】

组件加载图像流程（源码 `P`/`M`/`I`）：
1. 图片源：`imgUrl` 为空时取 `'/static/sliderImages/' + (1~20 随机) + '.jpg'`，**同源图片**；
2. `new Image(); crossOrigin="Anonymous"`（同源下不影响可读性）；
3. 加载完成后在背景 canvas 上：绘制拼图块轮廓（`B(...,"fill")`，白色半透明描边填充）并把目标坐标随机化：
   - `A`（目标 X）= `random(T+10, l-(T+10))`，即约 **73–247**（l=320 时）；
   - `O`（目标 Y）= `random(10+2r, 160-(T+10))`；
4. 小块 canvas：`B(...,"clip")` 剪裁出拼图块 → `drawImage` → `getImageData(A-3, O-2r-1, T, T)` → `putImageData` 到 (0, O-2r-1)；
5. 刷新（`refreshIcon` 点击 / 失败重置 `I()`）：清空两 canvas、恢复滑块位置 0、重新随机选图。

**结论**：✅ 两个 Canvas 均真实绘制图像；背景 canvas 为完整拼图场景图，小块 canvas 为剪裁出的拼图块（可读：同源 + crossOrigin=Anonymous，`getImageData` 预期可用；若未来图片改为跨域无 CORS，则抛 `SecurityError`——诊断模块会把「不可读/被污染」作为一项发现记录）。

## 4. 事件绑定与状态机【已验证事实】

事件绑定（源码 render 部分）：
- `mousedown` / `touchstart` → 绑定在 **小块 canvas(.block) 与 .slider** 上（记录起始 `clientX/clientY`，置拖动标志 `S=true`）；
- `mousemove` / `touchmove` → 绑定在 **.vertifyWrap 根节点**上（拖动中，组件自身调用 `preventDefault`，非插件行为）；
- `mouseup` / `touchend` → 绑定在 **.vertifyWrap 根节点**上（结束判定）；
- `refreshIcon` → `click` 重置并换图。

拖动映射（源码 `z`）：
- `dx = clientX - 起始X`；`dx<0 或 dx+38>=l` 时忽略；
- 滑块遮罩宽度 `m = dx`；**滑块/小块左偏移 `left = (l-60)/(l-40) × dx`**（约 0.9286 倍）；
- 每次 move 把 **Y 轴位移量** `dy` push 进轨迹数组 `C`。

结束判定（源码 `j` + `R`）：
- 若抬起时 X 与按下时相同 → 忽略（视为未拖动）；
- 否则计算 `{spliced, verified}`：
  - `spliced = |sliderLeft - destX| < 10`（是否拼图到位）；
  - `verified = 轨迹数组Y轴标准差 ≠ 0`（源码注释原文：`// 简单验证拖动轨迹，为零时表示Y轴上下没有波动，可能非人为操作`）；
- 分支（源码 `j`）：
  1. `spliced && verified` → `sliderContainer_success` → `onSuccess()` → 播放器回调 `M`：**关闭弹窗 + `video.play()` + 3 秒后恢复打卡使能**；
  2. `spliced && !verified` → `sliderContainer_fail` + 文案「请再试一次」→ 立即 `I()` 重置（重新换图）；
  3. `!spliced` → `sliderContainer_fail` + `onFail()` → 1 秒后 `I()` 重置；
- 失败后弹窗不关闭、可无限重试；`refreshIcon` 也可手动换图重试。

**状态机**（弹窗生命周期，插件据此分派状态）：

```
加载(loadingContainer) ──图片就绪──▶ 待拖动(sliderContainer)
  待拖动 ──mousedown+move──▶ 拖动中(_active)
  拖动中 ──mouseup──▶ 判定：
    位置到位且轨迹波动 → _success → 弹窗关闭 → 视频恢复播放
    位置到位但轨迹无波动 → _fail+「请再试一次」→ 自动重置换图（可再拖）
    位置不到位 → _fail → 1s 后重置换图（可再拖）
  任意阶段 ──点击 refreshIcon──▶ 重置换图
```

## 5. 验证码与播放器 / 课程学习流程的交互【已验证事实】

学习页 → 播放器（`playVideo`）→ 验证码的完整链路：

1. 学习页 `detail` 挂载 `playVideo`，`playSrc` 含服务端下发的：`videoUrl`、`watchTime`（断点续播）、`clock`（**打卡时间点数组**）、`flag`（1=关闭打卡）、`coursesId`、`projectId`、`removalFlag`、`learnStatusValue`；
2. 播放器 `timeupdate`（含 500ms 轮询兜底，源码 `Z`）中判断：**`flag != 1` 且 `currentTime ∈ clock` 且打卡使能 `m`** → `video.pause()`、`exitFullscreen()`、弹窗置显（`a=true`）、打卡使能置否；
3. 弹窗内验证码 `on-success` → 关闭弹窗、`video.play()`、3 秒后重新使能打卡（下个打卡点再次弹出）；
4. 播放器另有：30s 节流的进度上报 `saveCoursesTime`（`O`）、快进检测（跳变 ≥5s 或连续 2 次 → 弹「请勿尝试快进视频，否则将判定为违规学习」并 seek 回退 + 暂停）、`visibilitychange=hidden` 时暂停、`ended` 时上报 `setLearningCousesStatus(status:1)` 并 `videoState(2)` 通知页面刷新课程状态（`Ia` → `getLearnProjectStatus`）；
5. 切课：点击课程列表 `<li>`（非当前项）→ `getCoursesInfo` 加载新课程 → 播放器以递增 key 重挂载（video 元素重建、src 变化）。✅ 这是插件「切换校验」依赖的可观察信号。

**补充：页面失去鼠标焦点时的暂停机制**
- ✅ 已验证：playVideo 组件内**没有** `blur/focus/hasFocus` 相关处理（全 bundle 检索 0 命中）；其暂停触发点为 `visibilitychange` 且 `hidden` 时 `video.pause()`（源码 `N` 处理器，偏移 559315）。
- ✅ 已验证：Chromium 在浏览器窗口失焦（切到其他应用）或被完全遮挡、切换标签页时，会把当前页面 `visibilityState` 置为 `hidden` → 平台随之暂停，表现为「页面失去鼠标焦点时可能暂停」。
- 插件处理（content.js）：`window blur`（被动）记录失焦时间用于 pause 归因 → 分类为「平台暂停」；`window focus` / `visibilitychange→visible`（均被动）时，若视频处于非用户暂停态，做**一次**安全恢复（5s 节流、用户主动暂停/验证码未完成/自动化暂停时不干预）。⚠️ 具体失焦是否触发隐藏因浏览器/系统/多显示器遮挡情况而异，此为【推测】，插件按「平台暂停」处理不影响正确性。

## 6. 自动化可行性结论（明确区分）

### 6.1 可以使用浏览器自动化实现（插件已实现）
| 行为 | 实现方式 | 说明 |
|---|---|---|
| 视频状态检测（播放/暂停/结束/平台暂停） | 原生事件 + 5s 轮询兜底 | 只读监测 |
| 视频结束后自动切下一节 | 点击课程列表下一项 `<li>` | 点击后校验「播放源/视频元素重建」真实变化 |
| SPA 播放器重发现 | MutationObserver | video 元素被重建时自动重绑 |
| 验证码弹窗出现→暂停自动切换 | MutationObserver + 轮询 | 弹窗出现即挂起，不点击、不绕过 |
| 弹窗关闭→复核页面→安全恢复 | 弹窗消失事件 | 非用户暂停才恢复播放（一次） |
| 验证码组件被动诊断 | 结构快照/Canvas 像素只读/事件与类变化观察 | 全部只读，不干预页面 |

### 6.2 技术上可模拟但插件明确不做（存在反自动化且属绕过人机校验）
- 拖动滑块到目标位置：组件内部随机目标 `destX` 每图刷新，视觉层可用合成指针事件把滑块移到位；
- **但组件内置「Y 轴轨迹标准差非零」检查**：纯水平/直线拖拽轨迹标准差为 0 → 必判「请再试一次」；要骗过该检查需要注入带 Y 波动的伪轨迹——这已属于绕过人机交互校验，且平台随时可能在后端增加校验，插件不做、不提供实现。

### 6.3 必须人工/后端处理的部分（自动化无法替代）
- **验证码人工完成**：拼图滑块需真人拖动（含 Y 轨迹波动），后端判定最终是否放行；
- **学习进度与完成判定**：服务端依据 `saveCoursesTime` 上报与课程状态接口判定，前端无法伪造「已学完」；
- **打卡时间点**：由服务端 `playSrc.clock` 下发，出现时机不可预测，必须逐次人工通过；
- **账号风险**：快进/切后台/异常轨迹会被平台判定为违规学习（源码已内置提示与惩罚逻辑）。

## 8. 推测内容（未在抓取包中直接证实）
1. **canvasWidth 差异**：当前线上包学习页传 262，现场观察 320 —— 推测为站点灰度/多版本部署或用户进入的入口不同（默认值即 320，与观察一致）。
2. **服务端是否校验打卡行为**：前端无验证 API，但不能排除服务端把「打卡点之后的进度上报连续性」作为隐式校验——插件按「必须人工完成」处理，不受影响。
3. **防自动化升级**：平台可能后续为验证码增加后端签名/行为风控——届时本报告 §6.2 的结论仍适用（不做自动滑动）。

## 9. 复现步骤（人工可复现验证）
1. 登录平台 → 进入任一「专业课」项目 → 打开课程学习页（挂载播放器）；
2. 播放视频至第一个 `clock` 打卡时间点（或点击列表课程切换后继续播放）→ 观察：视频暂停、全屏退出、弹出「打卡」对话框；
3. 对话框内：查看 `.vertifyWrap` 结构（F12 → Elements）；两个 canvas 尺寸应为 `canvasWidth×160` 与 `63×160`；`loadingContainer` 先显示「加载中」后隐藏；
4. 按住滑块拖动：`.sliderContainer` 添加 `_active`；滑块 left / `.sliderMask` 宽度 / `.block` 小块同步左移；
5. 对准拼图松手：成功 → `_success` 类出现后弹窗关闭、视频恢复播放；故意没对准 → `_fail` 类出现、约 1s 后自动重置换图并提示可重试；
6. 把滑块快速直线拖到目标附近松手（轨迹无 Y 波动）→ 出现「请再试一次」并自动重置——**可现场验证反自动化轨迹检查**；
7. 点击 `.refreshIcon` → 图片重新随机、滑块归零。

## 10. 插件侧落地（对应实现）
- `content.js` 验证码模块：`.vertifyWrap` 出现 → 状态 `CAPTCHA/WAIT_MANUAL`、暂停切课、启动被动诊断（结构/坐标/CSS/Canvas 像素/事件序列/类迁移记录）；
- 弹窗消失 → `postCaptchaRecheck()`：复核视频状态，若已结束则补切课，若暂停且非用户暂停则安全恢复播放一次；
- 诊断结论写回 `chrome.storage.local`（`hnyxDiag`），popup「验证码诊断」区展示最近会话；完整日志含【已验证】/【观察】/【推测】标签。
